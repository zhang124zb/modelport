# 默认模型

在“设置 → 默认模型”选择并点击“保存默认模型”。可选全部内置及自定义提供商已知的模型；需要更多模型时先到“模型提供方”配置连接并获取或手动新增、保存，再返回选择。页面显示当前会话模型，方便区分会话选择和全局默认值。删除自定义提供商不自动清除默认引用或改用另一服务，须手动重新选择。

## 生效范围

- 保存后用于当前未生成中的空白文本窗口、之后的新对话、空白启动，以及清空聊天后的空白页；未发送草稿不因保存而删除。
- 有历史的会话继续使用自己保存的模型。主界面临时切换某个会话模型不改写全局默认值，正在生成的请求保持发起时的模型。
- 常规设置“恢复上次会话”优先恢复该会话模型；“显示空白新对话”使用默认模型。恢复常规 / 对话 / 快捷键设置不会覆盖默认模型。
- 未配置或恢复自动选择时，保持兼容的本机 Ollama 首个可用模型策略；没有本机模型时保留连接提示，不自动改用云端。
- 已指定的模型不在当前列表中仍保留选择；可能需要测试连接或重新安装本机模型。不能使用时由原有请求错误提示处理，不自动换到另一家服务。
- 保存云端默认值不等于配置凭据，不会读取或写入 API Key 内容、自动发送聊天、购买模型或下载模型。发送前仍由现有凭据和请求边界检查保护。

修改仅在保存后生效；退出分类、Escape、关闭设置或原生窗口时保护未保存修改。“恢复自动选择”需确认，并且仍需保存，不改写历史记录。

## 存储与接口

独立存储键为 `modelport.preferences.models.v1`。结构只有 `chatModel: { provider, id } | null`，不保存颜色、显示名称、密钥、模型列表或聊天内容。提供方仅允许当前支持的三种，模型 ID 非空、最多 240 字符且拒绝控制字符；未知字段不保留。

缺失配置使用自动策略，默认值不主动写入；配置损坏不覆盖原数据，显示检查提示。用户明确检查保存前暂停新的空白对话生成；已有会话仍按已保存的模型工作。保存失败不改变生效值。聊天备份不包含此配置。

- `src/lib/model-defaults.ts`：类型、校验、存储与默认引用解析。
- `src/features/settings/DefaultsSettingsPage.tsx`：选择表单、未配置密钥 / 当前列表缺失提示、保存和公共退出保护。
- `SettingsPageProps`：`modelDefaults`、`modelDefaultsError`、`onSaveModelDefaults`，沿用现有 `modelChoices` 与凭据状态。
- `src/App.tsx`：`pickDefaultModel` 统一空白默认选择；实际模型调用、历史模型保存及原生安全凭据流程不改变。本机连接测试仅在尚未选择本机模型的占位状态填入发现结果，不改掉当前明确选择。

## 验证

- `node scripts/verify-model-defaults-store.mjs`：Node.js 24，持久化 / 校验 / 损坏和失败保护、旧数据兼容、自动本机选择、明确选择不回退；不触碰用户数据。
- `node scripts/verify-model-defaults.mjs <调试端口> [截图路径]`：仅全新隔离 WebView；选择、保存、退出保护、重启、Ctrl + N、连接测试、历史模型保留、常规启动选项、清空后默认值、缺失模型 / 损坏配置，以及真实 Ollama 请求的模型标识。结束恢复测试前聊天与偏好，不调用云端模型或写入凭据 / 资料库。
- 原有桌面、快捷键、常规设置、对话参数、技能和知识库回归仍验证未配置默认值时的兼容行为。
