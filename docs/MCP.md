# MCP 外部工具（0.11 首版）

ModelPort 是 MCP 客户端，不是 MCP 服务商。首版通过 Streamable HTTP 发现工具，再让支持工具调用的模型提出操作；所有实际调用都必须逐次确认。沿用现有 Rust / Tauri 请求架构，没有新增常驻 Node 后台，也不会下载或启动外部程序。

## 配置和使用

1. 在「设置 → MCP」填写服务名称和完整 MCP 端点，保存新服务；新服务默认停用。
2. 如服务需要认证，单独保存访问令牌。不要在地址里填写密码或查询参数，不需要填写 `Bearer` 前缀。
3. 点击「连接测试」查看协议和工具列表。客户端仅发送发现、初始化和工具列表请求，不发送 `tools/call`。测试仍会访问该服务并提交已保存的令牌；恶意服务器在收到请求时的自行行为不受客户端控制。
4. 审阅来源和工具参数，明确确认后启用服务。可单独关闭工具。
5. 在聊天输入区「工具」菜单选择当前对话需要的服务；新对话默认不选服务。
6. 模型提出调用后，核对确认框里的服务、地址、完整参数和结果接收方，再允许或拒绝。关闭提示或按 Esc 视为拒绝，没有“永久允许”选项。

Ollama 必须在 `/api/show` 中明确声明 `tools` 能力。OpenAI / DeepSeek / Gemini / 通义千问 / Kimi / 自定义服务首版使用 Chat Completions 工具协议，能否调用取决于具体模型和端点；不声称兼容所有模型。Claude 原生 MCP 工具调用及 OpenAI Responses 工具协议尚未接入，原有普通聊天不受影响。

MCP 对话以完整、非流式模型轮次处理工具选择和参数，界面按轮次更新文本；未启用工具时仍使用原有逐段文本流。不要把工具等待误认为普通流式生成。

## 必须了解的安全边界

- 远程端点必须为 HTTPS；HTTP 仅接受明确的本机回环 IP。首版拒绝私有网段、链路本地、保留地址及解析到这些地址的公网名称；不支持局域网 MCP。DNS 结果固定到当前连接，禁止代理、重定向、自动 HTTP 重试及响应解压。
- MCP 访问令牌单独存入 Windows 安全凭据库，不放入聊天、JSON 配置或 Git。模型 API Key 不发送给 MCP。修改端点前必须删除旧令牌。
- 每个确认只绑定当前请求内的一个原生保存的调用。界面只提交同意或拒绝，不能替换参数。配置、令牌或禁用工具改变后，旧选择或授权失效；正在发送的服务请求不允许修改配置。
- 工具描述、只读标记和结果都来自外部服务，不是可信命令或安全证明。模型、技能和返回资料不能授予权限，也不能绕过逐次确认。
- 允许操作意味着参数会发给 MCP 服务，返回资料会交给确认框指定的模型。资料可能包含私人文件、账户信息，云端模型与外部服务可能产生费用。
- 参数和结果会保存在未加密的本机聊天中，导出备份时也可能包含这些资料。勿在工具参数中填写密码或密钥；客户端只能识别并脱敏自己持有的 MCP 令牌，不能保证识别任意敏感内容。
- 停止会取消客户端等待及后续步骤，不会自动重试。已经发出的请求可能仍在服务器执行，不能保证撤销、删除、退款或远程中止；结果未知时需自行核查。
- 确认框不是系统沙箱，不能限制一个外部服务已经具有的文件或账户权限。只连接可信来源，给服务器账户最小权限，重要数据先备份。
- 重启不重放工具；导入备份保留惰性历史记录，但不恢复服务选择或授权。中断的操作不会自动续跑。损坏的可选工具记录恢复时仅丢弃该记录并标为中断，保留原聊天文字。
- 取消所有 MCP 服务或切换模型后，只沿用之前的普通文字回答，不携带原始工具结果及工具调用结构。关闭工具后如需基于具体原始资料继续提问，请自行审阅并明确提供必要内容，不会自动回传。
- 发布版 WebView 启用内容安全策略，阻止远程脚本、远程图片和外部页面嵌入；模型/MCP 内容只作为文字或安全 Markdown 展示，不作为可执行 HTML。

## 首版边界与限额

- 最多 16 个已保存服务、每对话最多选择 3 个；每服务最多 32 个工具及 4 页发现结果，每请求最多提供 64 个工具。
- 每次用户请求最多 5 次工具尝试、顺序执行；拒绝和错误也占用次数。每次确认最多等待 120 秒。
- Schema 最多 8 KiB，参数最多 16 KiB，工具结果最多 64 KiB，HTTP 响应最多 512 KiB；还有深度和节点数检查。
- 使用离线 JSON Schema 验证并拒绝 Schema 引用；不从网络或本机加载引用。复杂或超限的工具明确报错，不能绕过验证。
- 支持 2026-07-28 和 2025-11-25 / 2025-06-18 / 2025-03-26 的受限 HTTP 工具流程。不是完整 MCP 协议实现，不支持 stdio、OAuth 登录、旧 SSE-only、资源/提示模板、采样或额外用户输入请求。
- 旧协议会话不会保存在磁盘，也不会为析构清理而后台重发请求；服务端会话按其自身策略过期。界面的“启用/停用”是权限配置，不代表一个永久常驻连接。

## 开发入口与验证

- `src-tauri/src/mcp.rs`：服务保存、凭据、受限 HTTP 客户端、参数/结果验证和一次性授权。
- `src-tauri/src/connection.rs`：`stream_chat_mcp`，模型轮次、历史工具结果、停止和调用上限。
- `src/lib/mcp.ts`、`src/lib/mcp-history.ts`：前端命令、显示安全和惰性记录验证。
- `src/features/settings/McpSettingsPage.tsx`、`src/components/McpApprovalDialog.tsx`：服务管理、风险提示和逐次确认。

纯逻辑检查：`node scripts/verify-mcp-store.mjs`、`node scripts/verify-mcp-ui.mjs`。原生测试：`cargo test --manifest-path src-tauri/Cargo.toml --lib`。实际桌面验证：在专用空白 WebView 配置和仅本机调试端口下运行 `node scripts/verify-mcp.mjs <端口>`；脚本用临时回环 MCP/模型模拟服务，不调用云端模型、不读写真实文件，并只清理自己创建的服务和提供商。

0.11.0 发布验证：51 项原生测试通过，1 项需要 GitHub 网络的既有测试跳过；MCP / 设置 / 备份 / 附件纯逻辑检查通过。最终便携程序经过本机真实 HTTP 与桌面 IPC 验证，覆盖实际凭据库的虚构令牌保存/删除、元数据发现、拒绝/允许、历史不重放、停止及过期授权、配置变更失效、异常 Schema、重定向拦截和 920×680 / 1480×960 布局。未使用真实云端密钥，也未验证真实第三方 MCP 服务或所有模型。

官方协议参考：[工具](https://modelcontextprotocol.io/specification/latest/server/tools)、[传输](https://modelcontextprotocol.io/specification/latest/basic/transports)、[安全](https://modelcontextprotocol.io/specification/latest/basic/security_best_practices)。
