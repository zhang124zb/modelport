# 性能与构建缓存

## 低缓存开发

`src-tauri/Cargo.toml` 的 `profile.dev` 与 `profile.test` 使用 `debug = 0`、`incremental = false`，减少调试符号和增量编译产物；开发模式的断言 / 溢出检查等其他选项保持默认。发布模式未改变。

这不能让缓存为零：编译器仍保存依赖库、构建脚本和可执行文件；升级依赖、切换工具链或构建选项也可能增加占用。代价是修改后重编译可能更慢，断点 / 调用栈中的原生源码调试信息减少。需要完整原生调试时，可以在临时 PowerShell 中设置 `CARGO_PROFILE_DEV_DEBUG=2` 和 `CARGO_INCREMENTAL=1` 后运行开发构建，结束后关闭该终端或移除变量；不要把调试变量设为系统全局配置。配置含义见 [Cargo 官方 profiles 文档](https://doc.rust-lang.org/cargo/reference/profiles.html)。

普通用户仅运行 `release/ModelPort.exe`，不需要 Node.js / Rust，也不会创建 `target` 编译缓存；聊天和附件属于用户数据，仍会占用空间。

`scripts/manage-build-cache.ps1` 默认只报告大小。`-CleanDebug -WhatIf` 预览删除目标，`-CleanDebug` 只删除本项目 `src-tauri/target/debug`。脚本检查明确路径、目录链接和运行中的编译 / 调试进程；不删除源码、`node_modules`、发布缓存或 `release/`。清理后需要重新编译，不可直接恢复缓存，但不影响已构建的发布程序。

本次清理删除旧调试产物约 20.15 GiB；在低缓存模式下重新完成原生单元测试和桌面调试构建后，调试目录约 2.11 GiB。这是本机、当前工具链和该次构建组合的结果，不是所有机器或未来构建的固定上限。

## 长对话

- 保存：`chat-store.ts` 的 v2 索引引用独立会话记录。保持不可变状态更新，未修改会话的对象引用不变，保存时只序列化改变的会话。切换会话只更新小索引。
- 写入失败保护：先暂存新的会话版本，最后提交索引，再清理旧记录。失败不覆盖上一版；损坏索引 / 子记录继续受保护。旧 v1 只有在新索引保存成功后删除，正常 JSON 备份格式仍为 v1。
- 渲染：默认最近 80 条消息，每次加载更早的 80 条，保持当前滚动位置。只限制渲染，不删除完整聊天；发送给模型的上下文仍由“对话设置”中的完整问答轮数控制。
- 流式回复：正文约每 40 毫秒合并一次界面更新；完成 / 失败 / 取消时刷新尾部，工具授权和状态事件立即处理，不延迟安全确认。生成期间约每 400 毫秒保存一次，结束立即保存，窗口正常离开时刷新待保存内容。

仍会在启动时读取全部会话，搜索也使用完整内存记录；不是无限历史的虚拟列表或数据库。异常退出可能丢失尚未保存的最近一小段回复。localStorage 有容量限制，暂存新旧会话也需要额外空间。大量历史持续增长时，需要后续迁移数据库和按需读取；当前不引入新存储依赖，详见 [数据与恢复边界](./GENERAL_SETTINGS.md)。

## 重复验证

以下离线检查使用内存模拟存储和合成记录，不读取本机聊天：

```powershell
node scripts/verify-chat-performance-store.mjs
node scripts/benchmark-chat-store.mjs
```

基准样本为 40 个会话、4900 条消息，连续 50 次更新同一会话。对比旧版整库序列化与新版分会话保存，本次累计序列化量约为 48.25 MiB 与 9.98 MiB，减少约 79.3%。新版每次写一条会话记录和小索引，总写入次数不一定减少，但写入体积下降。脚本校验只更新活动会话、不变状态不写入、旧版本及时清理及导航仅更新索引；耗时仅代表该合成样本 / 本机内存实现，不代表真实硬盘或所有用户场景的加速比例。

```powershell
node scripts/verify-chat-performance.mjs <隔离窗口调试端口>
```

桌面检查先确认隔离窗口没有真实聊天，再写入 1000 条合成消息，验证首屏 80 条、加载后 160 条、滚动定位、切换重置和单会话写入。另用本机临时模型接口发送 402 段文本，验证末尾不丢失、停止 / 重启保留部分文本及损坏记录保护；不调用云端，不发送真实密钥。脚本创建的测试产物位于已忽略的 `release/`，结束恢复空白测试状态。隔离窗口启动与调试端口风险见 [README](../README.md#桌面回归检查)。

模块职责见 [项目结构](./ARCHITECTURE.md)。不通过真实用户数据试验迁移，也不以基准替代数据保护回归。
