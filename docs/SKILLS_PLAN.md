# Skills 模块规划

状态：首版指令型功能已实现于 v0.3.0，并通过原生测试、正式桌面交互和本机 Ollama 验证。规划基于 v0.2.6，整理日期：2026-10-07。实际用法和接口见 [Skills 使用与开发](./SKILLS.md)。

实现调整：采用单一原子保存的 JSON 库，同时保留指令原文和索引，避免两份文件不同步；导入与编辑复用 `save_skill`，另提供预览与详情读取命令。以下保留原规划供后续对照。

## 1. 定位与首版范围

Skills 是可复用的任务指导，例如翻译、文章润色、代码审阅。用户选择技能后，ModelPort 将该技能的指令交给当前模型；技能本身不是模型，也不意味着本机有对应的执行能力。

首版确定实现“指令型技能”，形成完整的本地管理和聊天使用流程：

- 新建、编辑、导入单个 `SKILL.md`，查看内容和校验结果。
- 搜索技能、启用/禁用、删除，并在重启后保留。
- 在聊天输入区选择一个已启用的技能，或选择“无技能”。
- 使用现有 OpenAI、DeepSeek、Ollama 请求链路，不新增中转服务。
- 消息记录选用的技能名称及内容版本，便于追溯。

首版不做技能市场、远程安装、自动匹配、多技能叠加、脚本执行、任意文件读取或 MCP 工具调用。这些能力需要额外的执行机制和授权，不是导入一个文件就能获得。

## 2. 当前代码的接入点

- `src/features/settings/pages.tsx` 中 `settingsPageComponents.skills` 目前指向通用预留页，可以独立替换。
- `src/App.tsx` 的 `sendMessage` 构造对话历史，调用 `modelport.streamChat`；失败重试和停止生成沿用当前逻辑。
- `src/lib/modelport.ts` 的 `ChatTurn` 和 Rust `validate_messages` 目前只接受 `user` / `assistant`。
- `src-tauri/src/connection.rs` 同时存在 `send_chat` 和 `stream_chat`。技能请求组装应由两条路径共用，避免仅修一条路径。
- `src/lib/chat-store.ts` 保存 WebView 聊天记录；技能库应独立保存，不混入密钥或聊天存储结构。

因此不能只做设置界面，也不能直接在前端历史数组中塞入 `system` 消息。建议保留历史消息的角色约束，通过独立的可选技能参数，由 Rust 层验证并组装模型请求。

## 3. 界面与交互

### 设置 → Skills

保留现有设置导航和浅色风格，右侧展示技能管理内容：

- 顶部：标题、数量、搜索框、“新建技能”和“导入技能”。
- 列表：显示名称、用途简介、启用状态及兼容性提示；支持“全部 / 已启用 / 已禁用”筛选。
- 详情：名称、用途描述、Markdown 指令编辑区、来源、版本及能力限制说明。
- 操作：保存、启用/禁用、删除。离开未保存的编辑内容时提示确认。
- 空列表：引导新建或导入；可提供翻译、润色、代码审阅三种可复制的模板，不自动安装或启用。

导入先预览、校验，再确认保存；导入项默认禁用，用户审阅后启用。同名导入必须询问替换或修改名称，不静默覆盖。替换只改 ModelPort 内部副本，不改用户选中的原文件。

### 聊天输入区

新增独立“技能”按钮，不改变现有对话/绘图模式的含义。打开后选择一个已启用技能，输入区显示“当前技能：名称”及清除入口。

- “已启用”表示可以选择，不代表每次聊天都会自动使用。
- 技能选择属于当前会话，不影响其他会话；新对话默认无技能。
- 发送时固定本次使用的技能版本。生成过程中，编辑、禁用等操作不会改变已经发出的请求。
- 技能内容发生修改时，下次发送前提示确认使用更新后的内容，不无提示地替换旧会话的技能。
- 禁用或删除技能后，后续请求不再使用它；清除对应会话的选择并给出提示，已保存消息不删除。
- 首版只记录名称及内容版本，不承诺旧版本指令的完整重放；编辑后重试使用当前配置，界面应说明这一点。

## 4. 文件格式与兼容范围

采用 Agent Skills 的 `SKILL.md` 指令文件形式：YAML 元数据头加 Markdown 正文。标准中的 `name` 和 `description` 是必填项，技能目录还可以带有脚本、参考资料和资源。[Agent Skills 格式规范](https://agentskills.io/specification)

首版明确标记为“指令文件支持”，不宣传完整的 Agent Skills 执行兼容：

- 读取并校验 `name`、`description`，正文作为任务指令。
- 保留 `license`、`compatibility`、`metadata` 等合法元数据；可另存中文显示名称。
- `allowed-tools` 或兼容性说明不产生任何实际权限。
- `scripts/`、`references/`、`assets/` 相关内容首版不执行、不自动读取。导入说明和编辑页常驻提示这一限制；不以简单的字符串匹配宣称已检测出所有资源依赖。
- 格式不合法、缺必填项、正文为空或超过限制时，显示具体原因，不进入可启用列表。

YAML 使用成熟解析器，拒绝不安全标签和过度复杂输入，不自写不完整的 YAML 解析器。具体依赖在实施时核对维护状态并锁定版本；这一轮不安装依赖。

## 5. 本地数据与开发接口

技能存入 Tauri 解析出的应用数据目录，不存放在源码目录、程序发布目录或 OneDrive 仓库内：

- `skills/<name>/SKILL.md`：用户确认保存的指令文件副本。
- `skills-state.v1.json`：版本化的本地索引，保存稳定内部 ID、显示名称、启用状态、来源和内容版本。
- 名称修改不改变内部 ID；内容版本使用稳定的内容摘要，用来发现外部编辑或请求期间的版本变化。
- 保存采用临时文件与安全替换；索引与内容不一致时报告恢复问题，不把损坏文件静默当成空技能库覆盖。

最少的数据对象：

- `SkillSummary`：ID、名称、显示名称、描述、内容版本、启用状态、兼容性提示。
- `SkillRecord`：技能摘要、指令正文与保留的元数据。
- `SkillReference`：ID、内容版本，供会话选择和请求使用。
- 消息上的技能记录：ID、名称、内容版本；旧消息没有此字段时按普通消息读取。

拟增加的操作：

- `list_skills`：读取技能摘要和诊断信息。
- `import_skill`：验证上传文本并保存内部副本；同名冲突要求明确处理。
- `save_skill`：新建或修改，检查预期内容版本，避免覆盖过期编辑。
- `set_skill_enabled`：修改可用状态；启用前必须通过校验。
- `remove_skill`：确认后删除技能库中的项目，不删除原始导入文件或聊天记录。

前端调用继续放入 `src/lib/modelport.ts`，不额外增加服务工厂或插件框架。聊天请求仅增加可选 `skill: SkillReference`；未指定技能时维持原行为。

## 6. 技能进入模型请求的流程

选择技能 → 发送 ID 与版本 → Rust 校验并读取正文 → 组装本次模型指令 → 走现有流式请求。

- Rust 只根据已登记 ID 解析技能，不接受前端传来的任意磁盘路径。
- 校验启用状态、文本上限和内容版本；内容已变化时返回明确更新提示，不能悄悄使用另一个版本。
- 读取后的正文在本次请求内固定，不随磁盘编辑变化。
- 原有历史消息仍按 `user` / `assistant` 校验；应用层在校验后加入技能任务指导。
- `send_chat` 与 `stream_chat` 共用请求组装逻辑；具体指令角色和消息排列逐个验证现有三个服务商，不假定所有接口都完全一致。
- 不把所有技能正文发给模型，只发送本次选中的技能。
- 已完成/停止/失败/中断的消息状态和停止生成行为不变。

“只有选中的技能才加载正文”沿用按需加载思想；未来接入自动激活时，再增加目录摘要和受控激活机制。[Agent Skills 客户端接入指南](https://agentskills.io/client-implementation/adding-skills-support)

## 7. 安全与资源边界

- 导入文件始终按文本处理，不能执行其中的命令、HTML 或脚本。
- 任务指导不得成为读取凭据、运行程序或扩大文件访问的依据；文本隔离和提示词约定不是权限隔离，实际权限仍由原生程序控制。
- 使用云端模型时，选中的技能正文会随请求发送给该模型服务商；启用/选择界面明确说明这一点，不发送其他技能或磁盘路径。
- 建议初始限制：单个导入文件不超过 128 KiB，指令正文不超过 64 KiB；这是输入保护，不保证每个模型都能容纳。超限拒绝，不静默截断。
- 文件导入只选择单个 `SKILL.md`，避免首版引入压缩包解包、目录遍历、符号链接跟随等额外风险。
- 日志记录技能 ID、内容版本和错误类别，不记录正文、完整本机路径、聊天内容或 API Key。

## 8. 实施顺序与验收

1. 数据基础：实现解析、校验、本地索引和安全保存；覆盖损坏文件、同名冲突、版本变化及路径边界。
2. 设置管理：将 Skills 预留页替换为管理页，完成新建、导入、编辑、启用、禁用、删除和重启恢复。
3. 聊天接入：加入选择器、可选请求参数、共用请求组装和消息标记。无技能时必须与现有行为一致。
4. 端到端验收后再发布功能版本；自动激活、工具权限、脚本执行、技能目录与资源导入放入后续独立阶段。

首版建议新增两个业务文件：`src/features/settings/SkillsSettingsPage.tsx` 和 `src-tauri/src/skills.rs`。其余改动落在现有设置映射、命令调用、请求组装和聊天存储中；只在确有复用需要时再拆模块。

验收至少检查：

- UTF-8/BOM、Windows 换行、多行 YAML 描述可以正常导入；无效 YAML、不安全标签、缺字段、空正文、超限文件明确拒绝。
- 保存和重启后内容与启用状态正确；损坏或冲突不会静默覆盖用户数据。
- 未选择、已禁用或已删除的技能不会进入后续请求；只使用选中的一个技能，不重复拼接正文。
- 会话切换不串技能，旧记录兼容读取，版本变化必须提示。
- 无技能时三家模型的请求结构不变；有技能时验证实际请求中的指令排列。优先用本机 Ollama 完成功能检查，云端付费请求另行取得测试授权。
- 停止生成、失败后编辑重试、小窗口、键盘操作和现有设置分类不回归。
- 任意路径、脚本命令、权限声明不能触发本机执行或读取密钥。

## 9. 范围确认

用户已确认首版采用“导入、编辑、选择技能，让模型按技能要求回答”的指令型方案。本规划建议手动选择、单技能，不引入执行引擎。

后续若增加脚本或 MCP，先补充执行隔离、可访问目录、工具授权和模型工具调用流程，再单独安排实施，不在现有文本请求上直接开放本机执行。
